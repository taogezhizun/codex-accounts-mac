# 0.4.0 提案：本地文件存储与菜单体验

状态：已进入本地实施与隔离验证，未迁移真实凭据、未发布。当前代码基线为 main `020054ccfbc06582431200652a99287da0251751`，已发布 App 为 0.3.2（build 6）。建议版本号 0.4.0，正式开发前核对是否已有新版本。

用户目标：个人 Mac 自用、开源、无需付费开发者账号；减少账号操作时的钥匙串弹窗；继续仅刷新当前登录账号。产品优先级由本轮讨论确定，取代[调研报告](../research/liuzhao1225-experience-review.md)中此前“保留钥匙串”的建议，但不改变对上游实现的事实判断。

## 2. 文件存储与迁移

### 新安装

正常运行采用文件存储一个后端，不做用户可随时切换的双存储模式。数据位于系统 Application Support 的 CodexAccounts 子目录；具体子目录与文件名在实现中确定，文件名不直接使用邮箱。目录权限 0700、凭据文件 0600，拒绝符号链接，使用临时文件、刷盘与原子替换，沿用实例锁。

完整登录令牌和恢复备份是未经过应用层加密的文件，文件权限不等同于钥匙串的逐应用访问控制。应用不主动上传这些文件，不把它们加入仓库或发布包；系统备份是否包含这些文件取决于用户的备份设置。首次迁移说明应直白交代这一点，不能称为“加密文件保险箱”。

保存、浏览器添加、导入、移除、切换、恢复和确认结果都改用文件后端。额度仍直接读 Codex 当前登录文件，只刷新匹配的已保存账号；迁移本身不改 Codex 的当前登录文件。

应用的账号存储与发布者的 Sparkle 签名密钥是两回事：更新签名私钥继续留在发布者钥匙串，公钥和签名校验保持不变。本版不移动或导出更新私钥。

### 旧用户首次打开

启动时只读元数据和本地存储版本标记，判断是否需要迁移，不自动探测钥匙串。用普通页面/提示条展示“迁移已保存账号”，提供“开始迁移”和“稍后”。说明旧记录读取可能触发一个或多个系统授权弹窗；这是一轮迁移，不承诺只有一个弹窗。

选择“稍后”或取消授权：仍可浏览旧列表、查看缓存、刷新当前账号、检查 App 更新；需要读写已保存凭据的操作提示先完成迁移。不在下一次定时刷新或打开窗口时自动重试钥匙串。浏览器添加/保存等写操作也要先完成迁移，避免新旧两套数据分叉。

### 主动迁移事务

1. 获取实例锁及操作锁；冻结本工具内账号增删、切换和更新安装，只读取注册账号对应的旧钥匙串项及恢复项，不遍历无关凭据。
2. 写入独立暂存区，检查每个账号身份匹配、完整内容可读、账号数量、备注/缓存保留情况，以及恢复记录的目录、原始认证、目标身份和 pending 状态。恢复项不存在与拒绝读取必须区分；未能读取不能视为没有备份。
3. 全部核验成功后，原子提交一份版本化完整快照，使账号凭据、元数据和恢复记录作为一个完整数据集启用；不能逐个切换账号的后端后直接显示成功。
4. 中断、磁盘写失败、权限错误或拒绝授权时不提交新后端；下一次启动识别为迁移未完成，允许用户主动重试。缺失/损坏的旧账号明确列出处理项，不默默丢弃。重试需幂等；不在日志里打印令牌。
5. 成功后只使用新文件后端，旧钥匙串项保留但不再读写，不自动清理。将来清理旧凭据属于单独的明确操作，可能再次需要系统授权。

旧数据的保留用于迁移失败时保持原状，不等于迁移后持续同步。后续新增、删除和 token 变化不会回写旧钥匙串，因此不能承诺再运行 0.3.2 会保留这些后续变化。必须在升级说明里标注这个兼容边界，不提供自动降级按钮。不同版本不能同时操作同一份数据。

## 3. 菜单与更新提示

### 状态栏用量

参考用户提供的 OpenUsage“图标 + 百分比”布局，使用本工具原创单色图标，默认显示当前账号的剩余额度，例如“图标 74%”。这里的 74% 明确定义为剩余，不推断截图中 OpenUsage 的计算口径。设置提供“在状态栏显示剩余额度”开关，关闭后仅保留图标；使用等宽数字减少数字变化时的抖动，并提供包含“剩余”的辅助功能标签。

沿用 `QuotaPresentation.summary`：仅在 Codex 额度组中选择剩余比例最低的窗口，不混合其他额度池。悬停显示当前账号的隐私处理后名称、所选周期、剩余比例与真实更新时间。隐藏邮箱设置同样适用于提示文本。

只展示当前认证文件身份匹配的已保存账号数据；这不额外承诺 Desktop 界面已确认登录。切换待确认时显示“—”，提示正在等待核对；账号变更、退出或身份不匹配时立即移除旧账号数字。无数据或没有 Codex 额度窗口也显示“—”，不能用 0% 或 100% 代替未知。缓存过期或刷新失败时显示“~74%”并在悬停中说明“上次记录”及时间；正常刷新期间保留原值，不插入闪动的加载动画。

状态栏订阅现有账号与额度状态，复用当前账号刷新调度，不额外发网络请求或读取钥匙串。低额度不触发自动切换；打开菜单继续查看具体周期和账号详情。

### 账号列表

当前账号使用浅色底、文字标识和细额度条；不只依赖颜色。保留原创图标、备注、套餐信息、搜索及账号较多时的滚动。将低频恢复入口放入更多操作，已检测到待恢复状态时仍显示明确入口。

菜单额度摘要明确标注所属周期，继续选择 Codex 同组中更紧张的窗口；完整详情保留所有周期和额度组。不将两个额度池相加，也不为了界面简洁隐藏实际已耗尽的窗口。未知额度显示“未读取”，不显示 0%。

非当前账号使用“上次记录 · 时间”表述，即使刚刚切走也不暗示还在实时刷新。当前账号刷新失败保留上次值并标旧；刷新时不清空整行，不用整页阻塞弹窗。时间来自真实缓存时间，不在渲染或重启时伪造“刚刚更新”。

### 菜单内更新

在菜单底部显示可用新版本号和“查看更新”，正常无更新时不占常驻提示空间。用户点击后进入现有 Sparkle 确认与安装；账号操作、迁移与安装互斥。

可用版本来源应复用 Sparkle 对已验证更新源的发现结果，不另建一套无签名 GitHub API 更新判断。实现前核实当前固定 Sparkle 版本可用的委托回调与通知行为，确保不会同时出现重复的提醒/窗口。关闭本次更新窗口不能被误报为升级成功；重开后按当前版本清理旧提示。继续使用现有 HTTPS、已签名 feed/ZIP 和原位更新。

## 4. 实施顺序与验收

先完成文件后端及迁移，再改菜单，最后同步文档并打包。实现顺序不意味着先发布一个只有迁移、尚未验证恢复的半成品。

| 阶段 | 必须看到的结果 |
| --- | --- |
| 文件后端 | 保存、读回、删除和恢复记录持久化通过；权限/符号链接/原子写失败/实例锁有隔离测试；正常业务调用路径没有 Keychain 依赖 |
| 迁移 | 空库、多账号、pending 恢复项、缺失凭据、拒绝授权、中途失败/崩溃后重试都得到明确状态；失败不启用部分数据，元数据与恢复项不丢失 |
| 防弹窗回归 | 非演示 AppModel 注入 Keychain spy：新安装与迁移完成后的启动、添加/保存、刷新、切换/恢复、移除、确认不调用旧钥匙串；只在明确迁移动作中允许调用 |
| 菜单与更新 | 虚构账号的浅/深色、零额度/未知/过期、多账号滚动均可读；状态栏验证 0%/100%/未知/缓存、多周期及额度组、切换待确认/账号变更/退出、开关持久化、隐私与辅助功能，且渲染不新增请求；更新可用、取消、失败、安装互斥及安装后提示清理可验证 |
| 本机验收与发布 | 用户暂停自己的任务后验收真实迁移、A/B 切换、恢复和工具重启；未完成前不宣称真实账号全流程通过。两种架构的包和签名校验通过，文档同步后再发布 |

自动测试只能验证调用路径和隔离行为，不能保证系统不会显示其他提示。产品承诺限于本工具的账号钥匙串授权；Apple 未公证应用的首次打开提示、系统文件访问提示或 OpenAI 浏览器登录不属于同一个问题。开发和自动验证不应退出当前真实 Codex Desktop。

## 5. 交付与署名

修改涉及存储抽象、旧钥匙串迁移适配器、AppModel 的迁移/恢复状态、账号菜单、状态栏标签及其设置开关和 AppUpdates，以及相关测试和文档。保留现有停任务确认、正常退出、切换前备份、失败恢复与 Desktop 实际账号核对；不照搬上游“辅助进程核对等于 Desktop 登录成功”的表述。

README、使用指南、安全说明、架构与验证记录应统一描述迁移完成后的文件存储和残留旧数据。同步更新关于页“凭据保存在钥匙串”的旧文案。借鉴交互思路时注明参考 liuzhao1225/codex-account-switcher；若实际采用其代码或实质性软件片段，随分发保留对应 MIT 版权与许可。继续保留既有 cjg1995/codex-account-switcher、OpenUsage 和 Sparkle 的正确署名。

本地实现采用单一 `local-store-v1.json` 原子快照，代替多文件数据代指针，避免元数据、凭据和恢复记录部分启用。版本为 0.4.0（build 7），Sparkle 接入 Gentle Reminders 原生回调。真实数据迁移和发布仍未执行；验证结果记录在 VALIDATION.md。
